# Посібник із локального тестування та безпечного розгортання нового функціоналу

Оскільки ваш бот є активним (Production) і ним користуються люди, впровадження великих змін безпосередньо в діючу версію є небезпечним. Цей посібник детально описує, як протестувати нову логіку сегментації локально та як розгорнути її за допомогою ізольованого Staging-середовища без жодної загрози для поточних користувачів.

---

## Частина 1. Як протестувати новий функціонал локально

Cloudflare Workers та Wrangler мають чудову підтримку локальної розробки. Ви можете тестувати код на локальній машині трьома способами — від найпростіших автоматичних тестів до реального тестування через Telegram.

### Спосіб А: Автоматичні Unit та Інтеграційні тести (Vitest)
Це найшвидший і найбезпечніший спосіб локального тестування. Він не потребує Інтернету чи реальних ботів.

1. У вашому проєкті вже встановлено тестовий фреймворк `vitest`.
2. Ви можете написати тести для перевірки сегментації та логіки обробки вхідних запитів, не зачіпаючи жодного живого бота.
3. Запустіть тести локально командою:
   ```bash
   npm run test
   ```
   Або запустити у режимі постійного відстеження змін:
   ```bash
   npx vitest
   ```

*(Приклад тесту для перевірки розбиття тексту наведено у файлі `doc/multilingual_implementation_plan.md` у Кроці 5).*

---

### Спосіб Б: Локальний запуск (Wrangler Dev) + Симуляція запитів через `curl`
Цей спосіб дозволяє запустити локальний вебсервер воркера та надіслати йому тестові Telegram-повідомлення (webhook payloads) прямо з вашого терміналу.

1. **Запустіть локальний сервер розробки:**
   ```bash
   npx wrangler dev
   ```
   Wrangler запустить ваш воркер локально, зазвичай на адресі `http://localhost:8787`. У консолі ви будете бачити всі `console.log`, які викликаються у вашому коді.

2. **Перевірте локальні змінні оточення (секрети):**
   При локальному запуску Wrangler шукає файл `.dev.vars` у корені проєкту для зчитування секретів. Створіть файл `.dev.vars` у корені проєкту та запишіть туди тестові токени (якщо хочете перевірити повну інтеграцію з Gemini API локально):
   ```ini
   GEMINI_API_KEY="ваш_тестовий_ключ_gemini"
   TELEGRAM_BOT_TOKEN="ваш_тестовий_токен_telegram_бота"
   ```
   *(Увага: Ніколи не комітьте файл `.dev.vars` у Git, він вже доданий у ваш `.gitignore` за замовчуванням).*

3. **Надішліть симульоване повідомлення від Telegram:**
   Відкрийте інший термінал (або використовуйте Postman / Thunder Client у VS Code) і виконайте `curl`-запит, який імітує отримання повідомлення від Telegram:
   ```bash
   curl -X POST http://localhost:8787 \
     -H "Content-Type: application/json" \
     -d '{
       "update_id": 10000,
       "message": {
         "message_id": 999,
         "from": {
           "id": 12345,
           "is_bot": false,
           "first_name": "TestUser"
         },
         "chat": {
           "id": 12345,
           "type": "private"
         },
         "date": 1610000000,
         "text": "Привіт, my name is Петро та я вчуся."
       }
     }'
   ```
   У вікні запущеного `wrangler dev` ви миттєво побачите, як ваш код сегментує текст, які дані відправляються до Gemini і чи виникають помилки.

---

### Спосіб В: Повноцінний локальний запуск із живим Telegram (через тунель)
Найбільш наближений до реальності спосіб: ви пишете повідомлення у своєму телефоні тестовому боту, а код виконується локально на вашому комп'ютері, що дозволяє проводити інтерактивну відладку.

1. **Встановіть утиліту для створення тунелів (наприклад, `ngrok` або `localtunnel`):**
   ```bash
   npm install -g localtunnel
   # або завантажте ngrok (https://ngrok.com/)
   ```
2. **Запустіть локальний воркер:**
   ```bash
   npx wrangler dev
   ``` (воркер слухає порт `8787`).
3. **Створіть публічний тунель до вашого локального воркера:**
   - Для localtunnel:
     ```bash
     lt --port 8787
     ```
   - Для ngrok:
     ```bash
     ngrok http 8787
     ```
   Ви отримаєте публічну URL-адресу, яка перенаправляє трафік на ваш комп'ютер (наприклад, `https://smart-cats-jump.locallt.me` або `https://abc-123.ngrok-free.app`).

4. **Тимчасово переналаштуйте Webhook тестового бота на ваш локальний тунель:**
   Надішліть GET-запит у браузері або через curl:
   ```
   https://api.telegram.org/bot<ВАШ_ТЕСТОВИЙ_ТОКЕН_БОТА>/setWebhook?url=https://smart-cats-jump.locallt.me
   ```
5. **Тестуйте у реальному часі:**
   Пишіть вашому тестовому боту в Telegram. Кожне ваше повідомлення надходитиме на локальний комп'ютер, ви зможете бачити детальні логи, ставити точки зупину (якщо налаштовано дебаггер) та виправляти баги на льоту!

---

## Частина 2. Безпечне розгортання без зупинки Production-версії

Оскільки робочий бот зараз запущено і ним активно користуються, ми застосуємо концепцію **Staging Environment (тестове середовище)**. Це копія вашого бота, яка працює на окремому сервері Cloudflare і прив'язана до іншого (тестового) Telegram-бота.

### Крок 1. Створення тестового бота (Staging Bot)
1. Зайдіть у Telegram до `@BotFather`.
2. Створіть нового бота (наприклад, `ВашБот_Staging_Bot` або `test_checker_bot`).
3. Збережіть його токен (`TELEGRAM_BOT_TOKEN` для staging).
4. *(Опціонально)* Додайте бота до вашого тестового топіку чи групи, якщо тестуєте роботу в конкретних гілках (тредах) супергруп.

---

### Крок 2. Налаштування середовища Staging у `wrangler.jsonc`
Для того, щоб розділити версії, ми налаштуємо `environments` у Cloudflare. Відкрийте ваш файл `wrangler.jsonc` і додайте блок конфігурації для оточення `staging`.

Ваш оновлений `wrangler.jsonc` буде виглядати так:

```jsonc
{
	"$schema": "node_modules/wrangler/config-schema.json",
	"name": "telegram-bot-worker",
	"main": "src/index.js",
	"compatibility_date": "2026-08-25",
	"observability": {
		"enabled": true
	},
	"upload_source_maps": true,

	// Конфігурація для тестового (staging) середовища
	"env": {
		"staging": {
			"name": "telegram-bot-worker-staging"
		}
	}
}
```

---

### Крок 3. Додавання секретів для Staging середовища
Тепер нам потрібно завантажити секрети (токени) окремо для тестового сервера.
Виконайте у терміналі наступні команди (зверніть увагу на прапорець `--env staging`):

1. **Додаємо токен тестового бота:**
   ```bash
   npx wrangler secret put TELEGRAM_BOT_TOKEN --env staging
   ```
   *(Введіть токен вашого створеного тестового бота).*

2. **Додаємо API-ключ Gemini (можна використовувати той самий або окремий тестовий):**
   ```bash
   npx wrangler secret put GEMINI_API_KEY --env staging
   ```

---

### Крок 4. Деплой Staging версії воркера
Тепер задеплоїмо код з вашої нової Git-гілки на staging-сервер:
```bash
npx wrangler deploy --env staging
```
Після успішного деплою Wrangler виведе у консоль URL-адресу вашого staging-воркера. Вона буде відрізнятися від продуктової і матиме вигляд на кшталт:
`https://telegram-bot-worker-staging.<ваше-субдомен>.workers.dev`

---

### Крок 5. Встановлення Webhook для тестового бота
Тепер зв'яжемо вашого тестового Telegram-бота з деплоєним staging-воркером. Надішліть GET-запит (через браузер або curl):
```
https://api.telegram.org/bot<ТОКЕН_ТЕСТОВОГО_БОТА>/setWebhook?url=https://telegram-bot-worker-staging.<ваше-субдомен>.workers.dev
```
Вам має повернутися JSON з повідомленням `"Webhook was set"`.

**Вітаємо! Ваш тестовий стенд готовий.** Ви можете користуватися тестовим ботом, він працює на новому коді, окремо від основного бота. Реальні користувачі продуктової версії нічого не помітять, а ви зможете відловити всі баги.

---

### Крок 6. Фінальний реліз у Production (Go-Live)
Коли ви переконалися в тестовому боті, що сегментація працює ідеально, підтримка німецької, французької чи іспанської мов є стабільною і жодних багів немає:

1. **Зробіть злиття (Merge) вашої гілки** з новим функціоналом у головну гілку (`main` або `master`).
2. **Задеплойте код у Production:**
   ```bash
   npx wrangler deploy
   ```
   *(Ця команда оновить живого бота за 1-2 секунди без будь-яких простоїв у роботі).*
3. **Безпека відкату (Rollback):**
   Якщо після деплою в продуктивній версії виявилася критична помилка, ви можете миттєво повернутися до попередньої стабільної версії:
   - Перейдіть у панель керування Cloudflare.
   - Оберіть ваш Worker -> розділ **Deployments**.
   - Натисніть кнопку **Rollback** навпроти попереднього успішного деплою. Бот миттєво повернеться до старої робочої версії.
